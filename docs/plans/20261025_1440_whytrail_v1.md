# whytrail v1: link plan files and code both ways, in time order, plus a backfill for old work
Worktree: /home/ukd/projects/whytrail-v1
Branch: feat/v1
Summary: A tool that links each plan to the code it changed and back, in time order, so we can always see why code exists.

## Goal
- Owner (2026-10-25 ~14:40): "every piece of code that we wrote is from plan file … the plan file could have a section that says these were the files edited … the code also can have a section which links it to the plan files associated with that code … in a time bound way … first we need to find which plan files belong to which code … this tool you can just map out the timeline of events with the plan files and the code itself … new restroom [neurastream] can be one of the consumers … should be in the same ecosystem". Main checked: no tool does this (git-ai and ORG-2 link lines to AI prompts/sessions; aiblame to agent names; none to plan files, none backfills). The name `planlink` is taken on npm; `whytrail` is free.
- Done = a Bun/TypeScript CLI `whytrail` (own repo, npm package `whytrail`) that (1) answers `whytrail why <file>[:<from>[-<to>]]` with every plan behind those lines, oldest first, each with date, title, first Goal line, current plan path and the commits; (2) answers `whytrail code <plan-id|path>` with the commits and files that plan changed, in time order; (3) stamps new commits with a `Plan: <plan-id>` trailer through git hooks and refuses commits without one; (4) backfills links for old commits into a committed `.whytrail/links.jsonl` with a source and a confidence for each link, and lists unsure ones for the owner to accept or reject.

Memory logs with a files section (`## FILES MODIFIED`, e.g. /home/ukd/Work/pm-mr196/docs/memory/20260827_1344_jurisdiction_content_location_validator.md:17-22): CP 476 of 540, PM 1544 of 1572. Plans with a `Branch:` line: neurastream 53/69, PM 20/821, CP 8/209. Commit messages naming a plan today: neurastream 1/418, PM 32/4075. Neither the CP nor the neurastream repo has a commit-msg hook (PM has pre-commit and pre-push only).
- INCIDENT I-20261025-168 (owner correction, 2026-10-25 ~19:30): labels come from the plan stories, not from blame or the code diff: "I asked you to look at the documents behind those code change … in the plan file itself there will be a story whether this was born out of a bug or a performance … based on that story we can judge whether the previous code on which this was overwritten or built on top of was good or bad". Main had put labels in a separate tool built on `git blame`; wrong. Labels are a whytrail feature: a later plan's story judges the earlier plan whose code it changed.
- INCIDENT I-20261025-169 (owner, 2026-10-25 ~19:45): which earlier plan a later plan judges comes from the lineage, built from meaning plus dates: "we can do semantic matching … based on the dates of those files … if the plan is written before the code, the gap can be … 15 days … we hash every file … only read the files whose hashes have changed … have a metadata where we just summarize the outcome of each of those plans … the newer plan has more weight". Plan discovery: in the repo's main checkout (from `git rev-parse --git-common-dir`, so it works from any worktree), files matching `.whytrail.json` `plans` globs (default `docs/plans/**/*.md`, skipping `blockers/`, `assets/`, `INDEX.md`, `CANCELLED.md`); title = first `# ` line, date = the `YYYYMMDD_HHMM` stamp. Trailer parse: every `Plan:` trailer (several allowed) via `git log --format=%(trailers:key=Plan,valueonly)`. `why`: with a line range use `git blame --line-porcelain -L`; without one use `git log --follow`; map commits to plans; group by plan; oldest first; `--json`. `code`: commits carrying that plan's ID and their files (`git show --name-status`), time order. A plan ID with no file prints `(plan file not found)` instead of failing. — difficulty: 3 — verify: `cd /home/ukd/projects/whytrail-v1 && /home/ukd/Work/heavy-run.sh agent "whytrail p1" -- bun test && bun src/cli.ts --help | grep -q why`
- [x] P2 Write side. `whytrail install` puts `prepare-commit-msg` and `commit-msg` into the common git dir's hooks (or `core.hooksPath` if set), chaining any hook already there (keep it as `<hook>.whytrail-chained`, call it first, keep its exit code); `install` twice is a no-op; `uninstall` restores. prepare-commit-msg adds `Plan: <id>` when `WHYTRAIL_PLAN` is set, else when exactly one plan's `Branch:` line equals the current branch; never adds a duplicate. Git reads only the LAST paragraph as the trailer block (`-m x -m "Plan: a" -m "Plan: b"` drops `Plan: a`), so the hook appends a new `Plan:` line into the existing trailer paragraph, never as a separate paragraph; test it with a message that already has another trailer. commit-msg refuses (exit 1, one-line fix hint) a commit with no `Plan:` trailer unless the trailer is `Plan: none - <reason>` (reason required); merge, revert, fixup and squash commits pass. — difficulty: 3 — verify: `cd /home/ukd/projects/whytrail-v1 && /home/ukd/Work/heavy-run.sh agent "whytrail p2" -- bun test tests/hooks.test.ts`
- [x] P3 Backfill. `whytrail backfill [--dry-run] [--since <date>]` writes `.whytrail/links.jsonl` lines `{"commit","plan","source","confidence"}`, idempotent (re-run adds nothing), never overwriting a `review` decision. Sources, strongest first: `trailer` (high); `co-commit`: the commit changes the plan file and other files (high); `memory-log`: `docs/memory/<plan-id>.md` lists files under a files heading (`FILES MODIFIED`, `Files changed`, `Files`), and a commit within the plan's dates changes those files (medium); `progress-sha`: the plan text cites the commit's SHA (high); `branch`: the plan's `Branch:` line equals a merge commit's "Merge branch '<b>'" (high for the branch's commits); `date-files`: only a date match plus a code path cited in the plan (low). `why` and `code` read links.jsonl alongside trailers and show the source when it is not `trailer`. `whytrail review` lists low and conflicting links; `review --accept|--reject <sha> <plan-id>` records the decision. - [ ] P3b Lineage + story labels (INCIDENT I-20261025-168, INCIDENT I-20261025-169). (a) Link order, cheapest sure signal first: the P3 sources; then `cited-path` (the plan names a file the commit changes); only leftovers go to `semantic` = embedding similarity of plan text vs commit message + diff summary, inside a date window. The windows are measured, not guessed: from the high-confidence links, the 95th percentile of (code date − plan date) for plan-before-code and of (plan date − code date) for plan-after-code, written to `.whytrail/windows.json` and printed. (b) Cache by git blob hash: `.whytrail/cards.jsonl` holds one card per plan blob `{blob, plan, born, builds_on, files, outcome, confidence, source}`; a plan whose blob hash is unchanged is never re-read. Lineage queries read only cards, never plan bodies; in a lineage newer cards weigh more (weight = 0.5^(age_days/30)). (c) Story per plan: `Born from: bug|perf|feature|change|taste` (taste = the owner disliked a working thing) and `Builds on: <plan-id>[, …]`. Plans with those lines: read as-is (source `field`, confidence 1). Plans without them: one OpenRouter model (owner 2026-10-27: OpenRouter only for now, key from env `OPENROUTER_API_KEY`; model ids in `.whytrail/config.json` `{classify_model, embed_model}`, sensible defaults, any OpenRouter model works) answers, via chat completions with a JSON-schema response, `born` (one of the five) over the plan's Goal section plus a yes/no "B builds on A" with a 0–1 confidence for each candidate pair the lineage gives, and writes the card's `outcome` line; `semantic` in (a) uses OpenRouter's embeddings endpoint with `embed_model`; confidence ≥ 0.8 → keep (source `llm`), below → `unclassified`. One small HTTP module, no SDK dependency; tests inject the HTTP client. No API key → those plans stay `unclassified`, never guessed. (d) `whytrail labels [--json]`: `bad (bug|perf|taste) by <later plan>: "<its first Goal line>"` when a later bug/perf/taste plan builds on it; `good` when ≥ 14 days old and no such plan builds on it; else `open`; a feature/change plan building on it changes nothing. (e) `whytrail review --sample 30` prints 30 random llm cards for hand-checking; Main records agreement in Progress (target ≥ 90%). Bulk-commit noise (INCIDENT I-20261026-6, INCIDENT I-20261026-7): a commit touching more than 100 files (PM "wip-snapshot" 328-499, CP checkpoints) gets its co-commit links demoted to low confidence instead of high. Fixture tests, written fail-before (each fails on the P3 code, passes after): unchanged blob → no re-read (classifier stub call count 0); B `Born from: bug` building on A → A bad with B's Goal line; B `Born from: feature` → A not bad; classifier stub confidence 0.6 → fallback path taken; no key → `unclassified`; windows computed from fixture links equal the hand-computed percentiles; A 13 days old → open, 14 → good; a 300-file snapshot commit → its co-commit links land low, not high. — difficulty: 4 — verify: `cd /home/ukd/projects/whytrail-v1 && bun test tests/labels.test.ts tests/lineage.test.ts`
