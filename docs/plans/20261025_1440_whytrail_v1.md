- Owner (2026-10-25 ~14:40): "every piece of code that we wrote is from plan file … the plan file could have a section that says these were the files edited … the code also can have a section which links it to the plan files associated with that code … in a time bound way … first we need to find which plan files belong to which code … this tool you can just map out the timeline of events with the plan files and the code itself … new restroom [neurastream] can be one of the consumers … should be in the same ecosystem". Main checked: no tool does this (git-ai and ORG-2 link lines to AI prompts/sessions; aiblame to agent names; none to plan files, none backfills). The name `planlink` is taken on npm; `whytrail` is free.
- Done = a Bun/TypeScript CLI `whytrail` (own repo, npm package `whytrail`) that (1) answers `whytrail why <file>[:<from>[-<to>]]` with every plan behind those lines, oldest first, each with date, title, first Goal line, current plan path and the commits; (2) answers `whytrail code <plan-id|path>` with the commits and files that plan changed, in time order; (3) stamps new commits with a `Plan: <plan-id>` trailer through git hooks and refuses commits without one; (4) backfills links for old commits into a committed `.whytrail/links.jsonl` with a source and a confidence for each link, and lists unsure ones for the owner to accept or reject.

- [ ] P3b Lineage + story labels (INCIDENT I-20261025-168, INCIDENT I-20261025-169). (a) Link order, cheapest sure signal first: the P3 sources; then `cited-path` (the plan names a file the commit changes); only leftovers go to `semantic` = embedding similarity of plan text vs commit message + diff summary, inside a date window. The windows are measured, not guessed: from the high-confidence links, the 95th percentile of (code date − plan date) for plan-before-code and of (plan date − code date) for plan-after-code, written to `.whytrail/windows.json` and printed. (b) Cache by git blob hash: `.whytrail/cards.jsonl` holds one card per plan blob `{blob, plan, born, builds_on, files, outcome, confidence, source}`; a plan whose blob hash is unchanged is never re-read. Lineage queries read only cards, never plan bodies; in a lineage newer cards weigh more (weight = 0.5^(age_days/30)). (c) Story per plan: `Born from: bug|perf|feature|change|taste` (taste = the owner disliked a working thing) and `Builds on: <plan-id>[, …]`. Plans with those lines: read as-is (source `field`, confidence 1). Plans without them: Jev (TypeSafe AI API, key from env `TYPESAFE_API_KEY`) answers a Choice `born` over the plan's Goal section, and a Noul "B builds on A" for each candidate pair the lineage gives; confidence ≥ 0.8 → keep (source `jev`); below → GLM fallback writes the card (source `llm`); the `outcome` line of every card is written by the LLM (Jev does not generate text). No API key → those plans stay `unclassified`, never guessed. (d) `whytrail labels [--json]`: `bad (bug|perf|taste) by <later plan>: "<its first Goal line>"` when a later bug/perf/taste plan builds on it; `good` when ≥ 14 days old and no such plan builds on it; else `open`; a feature/change plan building on it changes nothing. (e) `whytrail review --sample 30` prints 30 random Jev cards for hand-checking; Main records agreement in Progress (target ≥ 90%). Bulk-commit noise (INCIDENT I-20261026-6, INCIDENT I-20261026-7): a commit touching more than 100 files (PM "wip-snapshot" 328-499, CP checkpoints) gets its co-commit links demoted to low confidence instead of high. Fixture tests, written fail-before (each fails on the P3 code, passes after): unchanged blob → no re-read (classifier stub call count 0); B `Born from: bug` building on A → A bad with B's Goal line; B `Born from: feature` → A not bad; classifier stub confidence 0.6 → fallback path taken; no key → `unclassified`; windows computed from fixture links equal the hand-computed percentiles; A 13 days old → open, 14 → good; a 300-file snapshot commit → its co-commit links land low, not high. — difficulty: 4 — verify: `cd /home/ukd/projects/whytrail-v1 && bun test tests/labels.test.ts tests/lineage.test.ts`
